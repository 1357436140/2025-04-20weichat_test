## 微信自动化：在微信内置浏览器打开指定链接
- 设备：Redmi 真机 HMEIUWY9XGNNTKIR，微信 8.0.79，未 root（user build）
- 实测结论：
  - `am start -a VIEW -d https://... -p com.tencent.mm` 必然报 unable to resolve：微信 manifest 无 https scheme，http 仅 `weixin.qq.com/r/` 前缀（GetQRCodeInfoUI）
  - 直接 `-n ...plugin.webview.ui.tools.WebViewUI` 报 SecurityException not exported
  - `weixin://dl/scan` 会落到 MMWebViewUI 的"当前页面无法访问"错误页，无任意 URL 深链
  - 可用的纯 adb 深链：`weixin://`（拉起微信）、`weixin://dl/...`（内部路由）
- 方案：Appium 走"文件传输助手"链路。已在 utils/weichat_utils.py 新增：
  - `enter_chat_by_search(keyword)` 搜索进入会话
  - `send_url_in_current_chat(url)` 输入框发链接
  - `wait_and_switch_webview(timeout, process_hint="tools")` 切 WEBVIEW（XWeb 进程 com.tencent.mm:tools）
  - `open_url_in_wechat(url)` 完整链路，已有相同链接消息则直接点，不重复发送
- 用户现有框架：Appium2 + UiAutomator2，driver.py 用 chromeOptions.androidProcess=com.tencent.mm:tools 切 webview
- 补全 launch_weichat：唤醒/解锁 -> activate_app(回退 am start) -> wait_weichat_home（等"通讯录"tab，停子页面自动 back，登录页报错）；
  force_stop_weichat、get_current_activity（dumpsys activity activities + 正则，避免 shell 管道被本地 shell 拦截）、is_weichat_home/is_weichat_login_page
- 实测：冷启动 6s 内到主界面；uiautomator dump CLI 在微信上返回空层级（381字节），但 Appium UiAutomator2 文本定位正常
- ExecuteCommand 注意：execute_shell* 拼命令用本地 shell=True，命令中的 | 和引号会被 Mac shell 吃掉，不要在 cmd 里写管道
- 实机端到端跑通"冷启动微信+打开百度"全链路，过程中解决四个关键问题：
  1. io.appium.settings 8.0.9(targetSdk35) 启动崩溃：FGS location 缺定位权限 → adb pm grant ACCESS_FINE/COARSE_LOCATION 等解决

## 入口差异定论 + 改用收藏入口（22:25）
- 实测对比同一域名（uatxyk.cibfintech.com）两个入口：
  - 文件传输助手（聊天场景）：落在微信拦截页，DOM data-module="urlweb"，请求根本不发出
  - 我→收藏→"测试环境首页"：前台 MMWebViewUI，地址栏显示 uatxyk.cibfintech.com、有加载进度条，页面空白是网络不通（未加 IP 白名单），**没有拦截页**
- 结论：微信外链风控按入口（scene）分级，聊天消息走链接安全预检，收藏（用户主动收藏的本地 favitem）不做该预检，所以同一 URL 收藏能进、聊天不能
- 代码调整：
  - 新增 open_fav_in_wechat(title) → 我→收藏→点标题→切 WEBVIEW
  - 新增 ensure_xweb_debug()（原 chat 链路仅保留用于打开 debugxweb.qq.com 开调试，open_fav 内部自动调用）
  - open_url_in_wechat 标记【已停用】，demo/test 均改用收藏入口
  - .gitignore 改 logs/**/*.log（原 logs/*.log 漏掉子目录 run.log）
