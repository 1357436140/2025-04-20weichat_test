## 1. 项目与方案概览

### 1.1 目标与适用范围

用真机微信驱动**微信内置浏览器里的 H5 页面**，做端到端 UI 自动化：从冷启动微信开始，进入业务入口、打开 H5、切到 WEBVIEW 上下文执行 DOM 断言，结束后还原现场，保证多条用例可以串行跑。

| 项目 | 说明 |
|---|---|
| 项目定位 | 微信内嵌 H5（信用卡账务类 WebApp）的端到端自动化测试 |
| 目标应用 | 微信 Android 版（实测 8.0.79） |
| 驱动方式 | Appium 3.8.0 server + UiAutomator2 driver + Appium-Python-Client 6.0.7 |
| 被测环境 | UAT 总链 `https://uatxyk.cibfintech.com/html/webapp/new_test/index.html`，业务页 `sitxyk.cibfintech.com` |
| 用例框架 | pytest（用例继承 `common/base_test.py::BaseTest`） |
| 运行平台 | macOS + USB 真机（adb），实测 Redmi `22041211AC` / Android 14 |

**适用**：安卓真机 + 微信内 H5（含 Vue/React 单页应用）、需要真实微信环境（登录态、微信风控、内置浏览器）的场景。

**不适用**：iOS（需另配 WebDriverAgent）、鸿蒙版微信（见 7.2）、纯接口测试、不需要微信环境的普通 Web 页面（直接用 Playwright/Selenium 更快）。

### 1.2 能力边界

| 能做 | 做不到 / 需绕行 |
|---|---|
| 冷启动微信、等待主界面就绪、登录态检测 | 免登录：登录态需要人工保持 |
| 从收藏入口打开指定 H5 并校验真实加载 | 用 `adb am start -d https://...` 直接打开任意链接（微信未注册 https 的 VIEW 过滤器） |
| 切 WEBVIEW 执行 DOM 查询、点击、取值 | 绕过微信对未备案域名的拦截（需配置业务域名或走收藏/扫码入口） |
| 结构化断言（文本/链接/CSS/正则/数量/页面状态） | 断言会随账务变化的数据（还款状态、金额、出账日）——只采集不断言 |
| 用例结束后还原微信首页、关闭 TalkBack | 保证 100% 无残留：系统级弹窗仍需 `watchers.py` 词表配合 |

- **第一次上手**：第 3 章（环境）→ 第 4 章（跑通 demo）→ 第 5.3 节（自己写用例）

## 2. 核心链路与技术决策

### 2.1 全景链路

```
开启 TalkBack（放开无障碍）
   → 唤醒/解锁屏幕
   → 冷启动微信，等「通讯录」tab 出现
   → 我 → 收藏 → 点条目（收藏入口不过外链风控）
   → 微信内置浏览器 MMWebViewUI 加载 H5
   → 确保 XWeb 调试已开 → 切 WEBVIEW_com.tencent.mm
   → 校验页面真加载（URL + 标题 + readyState）
   → 业务断言（点点点 + 结构化校验）
   → 还原：回首页 / 关 TalkBack / 可选杀进程
```

四个设计目标对应四类障碍：**能点得动**（无障碍被屏蔽）、**能进得去**（外链被拦）、**能断得准**（WEBVIEW 上下文与调试端口）、**能串得住**（用例间现场污染）。

### 2.2 无障碍：控件树读不到的对策（TalkBack）

**现象**：微信 8.0.79 上 `page_source` 只有空节点（`a11y-important=false`），`text("通讯录")` 定位必然失败，但界面明明正常。

**取证**（对照实验，别靠猜）：

| 场景 | page_source 体量 | 结果 |
|---|---|---|
| MIUI 桌面 | 88 KB | 元素齐全，说明无障碍本身正常 |
| 微信首页（未开读屏） | 约 0.7 KB 空节点 | 控件树对第三方无障碍服务不可见 |
| 微信首页（开 TalkBack 后） | 110 KB | 文本定位恢复，点击有效 |

**结论（行为层）**：在上述设备与微信版本上，微信对第三方无障碍服务不暴露控件树，开启系统读屏 TalkBack 后恢复。具体实现机制未证实，本文只采用"现象—可用解"这一层结论，不据此推断微信的内部策略。

因此自动化前置动作是开启 TalkBack。

**封装**：`enable_talkback()` / `disable_talkback()`，`launch_weichat()` 内部自动开启；结束时 `cleanup_after_test(close_talkback=True)` 自动关闭。

**坑**：关闭时必须用 `settings delete secure enabled_accessibility_services`。写成 `settings put ... ''` 时，空引号会被本地 shell 吞掉，命令缺参数、**静默失败**，现场表现是"跑完手机停在 TalkBack 教程页"。关闭后还要结束 TalkBack 进程清理其任务栈。

注意：`settings delete secure enabled_accessibility_services` 会清空设备上**所有**已启用的无障碍服务，不只 TalkBack。若设备还装有其它读屏或自动化服务，执行前应记录原值（`settings get secure enabled_accessibility_services`），结束后写回。

### 2.3 入口选择：收藏 vs 聊天消息

同一域名、同一账号下，两个入口的实机表现不同（差异为实测结果；微信内部的判定规则未公开，本文只按现象使用）：

| 入口 | 前台页面 | 实际行为 | 可用 |
|---|---|---|---|
| 聊天消息 / 文件传输助手 | 微信拦截页 | DOM `data-module="urlweb"`，文案"如需浏览，请长按网址复制后使用浏览器访问"，**请求根本不发出** | ❌ |
| 我 → 收藏 → 条目 | `MMWebViewUI` | 地址栏显示目标域名并真实发起请求（能否渲染取决于服务端 IP 白名单） | ✅ |

**决策**：业务入口统一走收藏，`open_fav_in_wechat(title, expect_url=...)`。可复现的差异在于：收藏条目是本地 favitem，打开路径与消息点击不同；推测其不经过消息层的链接安全预检，机制未证实，但现象稳定可依赖。

配套约定：

- 需提前在微信里**收藏一次**目标链接，标题传给方法（默认"测试环境首页"）；
- 方法内部调用 `wait_webview_loaded()` 做三重校验（URL 为 http(s)、标题不在错误页名单、`readyState == complete`），避免"页面没打开，用例却继续跑"的假通过；
- 聊天入口 `open_url_in_wechat(url)` 标记**停用并保留**，只用于已备案域名或临时调试；
- 文件传输助手链路只保留一个用途：打开 `debugxweb.qq.com` 开调试开关。

> 关于"不要在收藏里打开"：那是调研阶段针对**开启调试开关**的提示（开关页需在聊天窗口点击才生效）。结论不同是因为目的不同——开调试走聊天，跑业务走收藏。

**备选入口**：扫一扫（生成二维码 → 推入相册 → 扫一扫识别），可参数化任意 URL，通常也不受聊天风控限制，需要时再封装。

### 2.4 XWeb 调试与 WEBVIEW 上下文

**为什么必须开调试**：Appium 切 WEBVIEW 依赖 chromedriver 连接 XWeb 的 devtools socket。微信冷启动后该端口默认关闭。

| 项 | 现行做法（微信 8.0.7x+） | 历史做法（旧版微信 / X5 内核） |
|---|---|---|
| 开关页 | `http://debugxweb.qq.com/?inspector=true` | `http://debugx5.qq.com` → 信息 → TBS settings → 勾选 Inspector |
| 强制启用内核 | 不需要 | `http://debugmm.qq.com/?forcex5=true` |
| 上下文名 | `WEBVIEW_com.tencent.mm`（**主进程**） | `WEBVIEW_com.tencent.mm:tools`（子进程） |
| `androidProcess` | `com.tencent.mm` | `com.tencent.mm:tools`（已废弃，仅历史参考） |

排查要点：

- 调试端口形态是 `webview_devtools_remote_<pid>`，**必须确认 pid 属于微信进程**。曾出现 `webview_devtools_remote_9742` 属于后台系统浏览器、导致"切上下文成功但断言全挂"的假象；
- `ensure_xweb_debug()` 会先探测端口归属，未开启则自动打开开关页；开关改动后**必须杀掉微信进程重启**才生效，只切后台无效。微信冷启动后若探测不到端口，重新走一次开关页即可（该方法已自动化）；
- 调试端口需要转发时，**必须先确认真实 socket 名**，不能照抄固定名：

```bash
# 1) 找到微信 pid 与对应 socket
adb shell ps -A | grep com.tencent.mm
adb shell cat /proc/net/unix | grep webview_devtools_remote
# 2) 用真实 socket 名转发（<pid> 换成微信主进程 pid）
adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>
```

`chrome_devtools_remote` 是 Chrome 浏览器的 socket 名，用在微信上会转发到错误进程。

### 2.5 用例隔离与现场还原

`cleanup_after_test(stop_weichat=False, close_talkback=True, back_to_desktop=False)`

- **默认**：切回 `NATIVE_APP` → 逐级返回（内置浏览器 → 收藏/聊天页 → 首页，实测 2~3 次 `back`）→ 关闭 TalkBack → 可选回桌面；
- **`stop_weichat=True`**：直接 `am force-stop`，隔离最彻底，代价是下次冷启动要重新打开调试开关（多一次开关页访问）；
- 用途：上一条用例深入到多层级页面后，下一条仍能从首页干净开始，这是**串行用例**的前提。

选择建议：普通只读用例用默认（快）；会改数据或强依赖首屏状态的用例用 `stop_weichat=True`。

**边界**：还原只恢复客户端现场（页面、进程、无障碍），**不回收业务数据**。用例若产生还款、分期、绑卡等写操作，必须另做数据准备与清理，杀进程不能替代回滚。

### 3.2 主机环境（macOS）

1. **JDK 17**（Temurin）：`https://adoptium.net/temurin/releases/?version=17`，装 DMG 后配置 `JAVA_HOME`；
2. **Android SDK**：`platform-tools` + `build-tools`，配好 `ANDROID_HOME`、`ANDROID_SDK_ROOT` 与 `PATH`；
3. **Node.js（20.19+ / 22.12+ / 24+）与 npm ≥10**：`node -v`、`npm -v`；再 `npm i -g appium`，校验 `appium --version`；

5. **Appium Inspector**（可选，定位原生元素用）：首次需装插件 `appium plugin install --source=npm appium-inspector-plugin`，启动时加 `--use-plugins=inspector`，浏览器开 `http://127.0.0.1:4723/inspector`。

```bash
# 校验
java -version          # 应输出 temurin 17
adb devices            # 设备状态必须是 device，不能是 unauthorized
appium --version
```

### 3.3 手机侧准备

1. 开发者选项 → **USB 调试**开启（无线 adb 容易识别失败，优先用数据线，且必须是**能传数据**的线）；
2. 首次连接在手机上确认授权，`adb devices` 显示 `device`；
3. 设置 → 无障碍 → 检查 TalkBack 可用（自动化会**程序化开启/关闭**它，见 2.2）；
4. 关闭锁屏密码或保持常亮，避免会话中途息屏；
5. 保持微信已登录；被测 H5 需**提前收藏一次**（2.3）。

### 3.4 首次运行前的三项检查

| 检查项 | 症状 | 处理 |
|---|---|---|
| `io.appium.settings` 权限 | 会话创建报 `Appium Settings app is not running` | `pm grant` 授予两个定位权限（见下） |
| 辅助应用是否完整 | 卸载后 Appium 不自动重装，仍报 settings 未运行 | 彻底卸载四个 `io.appium.*` 包后重启会话重新推送 |
| 本机代理 | 客户端连不上 `127.0.0.1:4723` | 命令前加 `env -u http_proxy -u https_proxy ...` |

```bash
# 权限（MIUI 上缺定位权限会让 settings 的前台服务崩溃）
adb shell pm grant io.appium.settings android.permission.ACCESS_FINE_LOCATION
adb shell pm grant io.appium.settings android.permission.ACCESS_COARSE_LOCATION
# 注意：FOREGROUND_SERVICE_LOCATION 是普通权限，只能由 APK 清单声明，
# 不能用 pm grant 授予（会报 not a changeable permission type），不必执行。

# 需要彻底重装时：先全部卸载，确认无输出，再重开会话
adb -s <序列号> uninstall io.appium.settings
adb -s <序列号> uninstall io.appium.uiautomator2.server
adb -s <序列号> uninstall io.appium.uiautomator2.server.test
adb -s <序列号> uninstall io.appium.unlock
adb -s <序列号> shell pm list packages | grep io.appium   # 无输出才算干净
```

> 原理：Appium 从 2.x 起只有**检测到设备上不存在该包**时才会推送 APK。只删一个包、或内部缓存状态异常时，Appium 会误判"包还在"，重启服务也不会重装。

## 4. 快速开始

### 4.1 最小运行流程

```bash
# 0) 变量：按自己的环境替换
PROJECT=/path/to/2025-04-20weichat_test
PY=/Library/Frameworks/Python.framework/Versions/3.10/bin/python3   # 换成你的解释器

# 1) 启动 Appium（单独开一个终端，保持前台运行，不要关掉）
appium --port 4723

# 2) 确认设备在线（状态必须是 device）
adb devices

# 3) 跑演示脚本：冷启动 → 收藏入口 → 切 WEBVIEW → 还原
cd "$PROJECT"
env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy -u ALL_PROXY -u all_proxy \
  PYTHONPATH=$PWD "$PY" scripts/redmi_note_11pro/demo_open_test_url.py
```

### 4.2 执行用例

```bash
cd "$PROJECT"
env -u http_proxy -u https_proxy PYTHONPATH=$PWD \
  "$PY" -m pytest scripts/redmi_note_11pro/test_code_demo.py -s -v
```

> `PROJECT` / `PY` 见 4.1；在 PyCharm 里用 pytest 运行配置也可以，注意工作目录设为项目根、环境里去掉代理变量。

用例流程：冷启动 → 收藏入口打开总链 → 点 sit → 点微信 → 点"1、账单查询" → `check_bill_page()`（19 项结构断言）→ teardown 还原。

### 4.3 成功判据

1. 日志出现 `断言通过｜页面已加载：url=https://... title=... readyState=complete`；
2. 日志出现 `已切换到上下文: WEBVIEW_com.tencent.mm`；
3. pytest 输出 `1 passed`，且末尾有"用例状态还原完成（回首页=True）"；
4. 手机停在微信首页；无障碍服务与**运行前配置一致**（运行前没有其它读屏服务时，`adb shell settings get secure enabled_accessibility_services` 才返回 `null`；若有其它服务，应恢复原值而不是清空）。

参考耗时：完整一条约 100~115 秒（含冷启动、切上下文、还原）。

## 5. 工程结构与扩展

### 5.1 目录与模块职责

```
2025-04-20weichat_test/
├── confest.py                      # pytest 配置占位
├── common/
│   ├── assert_utils.py             # AssertUtils：断言唯一入口
│   ├── base_test.py                # 用例基类 BaseTest（setup/teardown）
│   ├── driver.py                   # Appium 会话工厂（Mac，当前使用）
│   ├── driver2.py                  # 备用驱动实现
│   ├── exec_cmd.py                 # ExecuteCommand：adb/shell/本地命令
│   ├── find_ui.py                  # 元素定位工具（resource-id/text/xpath）
│   ├── functions.py                # 设备信息、亮屏等
│   ├── global_attrs.py             # 路径常量（chromedriver 等）
│   ├── logger.py                   # 日志封装 + get_logger() 单例
│   ├── paths.py / decorators.py    # 占位
│   └── watchers.py                 # 系统弹窗监听词表
├── utils/weichat_utils.py          # 微信业务操作核心类（本项目核心）
├── scripts/redmi_note_11pro/       # 按机型划分的用例目录
│   ├── demo_open_test_url.py       # 演示脚本
│   └── test_code_demo.py           # pytest 用例（账单查询）
├── docs/                           # 本文档所在目录
├── logs/scripts_logs/run.log       # 运行日志（gitignore）
└── reports/                        # 报告输出（gitignore）
```

分层原则：`common` 提供基础设施 → `utils/weichat_utils.py` 提供微信业务动作 → `scripts/**/test_*.py` 只编排流程。

### 5.2 API 索引

**断言层 `common/assert_utils.py::AssertUtils`**

| 方法 | 说明 | 返回 |
|---|---|---|
| `assert_true(condition, msg="")` | 布尔断言 | `condition` |
| `assert_equal(actual, expected, msg="")` | 相等断言 | `actual` |
| `assert_element_present(driver, locator, timeout=10, msg="")` | 元素存在 | `WebElement` |
| `assert_span_text_present` / `assert_a_text_present` | span / a 文本 | `WebElement` |
| `assert_text_present(driver, text, ...)` | 任意标签文本（p/div/i…） | `WebElement` |
| `assert_native_text_present(driver, text, ...)` | 原生控件文本 | `WebElement` |
| `assert_css_present(driver, css, ...)` | CSS 选择器存在（无文字组件，如图片印章） | `True` |
| `assert_body_text_matches(driver, pattern, ...)` | 正文正则（金额/日期/版本号） | 匹配字符串 |
| `assert_text_count_at_least(driver, text, n, ...)` | 文本元素数量下限 | 实际数量 |

### 5.3 自己写脚本：三条铁律与四步法

**铁律**

1. 测试函数只编排流程，不写 `assert`、不写 `find_element`；
2. 断言只在 `common/assert_utils.py`，失败信息写清"哪个页面、缺什么、可能原因"；
3. 一个业务动作 = 一个业务方法："断言元素存在 → 动作 → 返回结果"，放在 `utils/weichat_utils.py`。

**四步法**（以新增"还款页"为例）

1. **探页面**：手动走到目标页，抓 `page_source` + 截图，确认区块标题、字段标签、按钮文案、可用于定位的稳定 class；
2. **补断言手段**（仅当现有不够时）：新形态才扩展 `AssertUtils`，如"元素可点击"；
3. **写业务方法**：

```python
def check_repay_page(self):
    """还款页结构检查：只断言固定标签与入口"""
    au = self.assert_util
    au.assert_text_present(self.driver, "还款金额", msg="还款页缺少「还款金额」字段")
    au.assert_text_present(self.driver, "立即还款", msg="还款页未出现「立即还款」按钮")
    return True
```

4. **用例只加一行**：`self.weichat_util.check_repay_page()`。

**断言边界**：一条断言在"业务正常"前提下，明天、下个月、换账号跑是否一定一样？不一定就别写进断言，改为采集写日志。

补充两点："全要素检查"指的是**结构与文案完整**，不是把所有可见数据都断言一遍；如果可变字段有确定的业务预期（固定测试卡、固定账单月），应当按预期断言，而不是一律放弃。

| 纳入断言 | 只采集不断言 |
|---|---|
| 路由、标题、区块标题、字段标签 | 金额数值 |
| 按钮/入口存在、稳定的数量关系（如「查账」2 个） | 还款状态（已还清/未还清/逾期，且印章是图片） |
| 固定版权主体文案 | 出账日期、营销角标、环境标识、版本号 |

**用例模板**


## 6. 元素定位与排障

### 6.1 微信原生元素

**前提**：TalkBack 已开启（2.2），否则读不到控件树。

| 工具 | 用途 | 备注 |
|---|---|---|
| Appium Inspector | 看层级、试定位表达式 | `appium --use-plugins=inspector` → `http://127.0.0.1:4723/inspector` |
| uiautomator2 / Weditor | 快速看页面结构 | `uiautomator dump` 在微信上可能返回空层级，属 CLI 局限 |
| 日志 + `get_current_activity()` | 确认当前 Activity | 排障时先看"到底在哪个页面" |

定位方式：`AppiumBy.ANDROID_UIAUTOMATOR` 的 `new UiSelector().text("收藏")` 最稳；`resource-id` 随微信版本变化（如 `com.tencent.mm:id/h5n` 已失效），需带兜底。

### 6.2 网页（H5）元素

```bash
# 1) 微信内打开 debugxweb.qq.com/?inspector=true（聊天窗口内点击），杀进程重启微信
# 2) 打开业务 H5，保持前台
# 3) Mac Chrome 打开 chrome://inspect/#devices，看到 WEBVIEW_com.tencent.mm + 域名 即可 Inspect
# 4) 需要端口转发时：
adb forward tcp:9222 localabstract:webview_devtools_remote_<微信pid>
```

定位写法（Vue 应用最常见）：

```python
# 文本在 span 里：//span[contains(normalize-space(.), "sit")]
def find_element_by_span_text(driver, text):
    return driver.find_element(By.XPATH, f'//span[contains(normalize-space(.),\'{text}\')]')

# 文本在 a 里：//a[contains(normalize-space(.), '1、账单查询')]
def find_element_by_a_text(driver, text):
    return driver.find_element(By.XPATH, f'//a[contains(normalize-space(.),\'{text}\')]')
```

稳定性经验：

- 优先"文本 + 标签"组合（`span`/`a`），少用 `data-v-*`（编译哈希，随构建变化）；
- 标签不确定时用 `//*[contains(normalize-space(text()),"…")]`，但要注意父子文本重复匹配；
- 无文字的组件（图片印章、图标）用 CSS class，如 `.paid-off`、`.amount`；
- 同一文本多处出现时（如"查账"有 2 个），用数量断言或加索引，别假设只有一个。

### 6.3 坑点清单

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | 元素读不到、`page_source` 为空 | 微信屏蔽第三方无障碍 | 开 TalkBack（`launch_weichat` 内置） |
| 2 | 链接变成"长按网址复制"页 | 聊天入口触发外链风控 | 改收藏入口；根治配业务域名/备案 |
| 3 | 切上下文报 chromedriver 连接失败 | XWeb 调试未开，或 `androidProcess` 写成 `:tools` | `ensure_xweb_debug()`；改主进程 `com.tencent.mm` |
| 4 | 会话创建失败 `Appium Settings app is not running` | settings 缺定位权限崩溃 | 按 3.4 授权 |
| 5 | 客户端连不上 `127.0.0.1:4723` | 本机代理变量拦截 | `env -u http_proxy ...` |
| 6 | shell 命令里的 `\|`、`''` 失效 | `ExecuteCommand` 用 `shell=True` 拼命令 | 整段取回 + Python 正则；空值用 `settings delete` |
| 7 | `Logger.info()` 多参数报 TypeError | 日志封装只收一个 msg | 用 f-string |
| 8 | `uiautomator dump` 返回空 | CLI 工具局限 | 用 Appium/UiAutomator2 instrumentation |
| 9 | 日志/驱动被提交进仓库 | 忽略规则不完整 | `logs/**/*.log`、`common/tools/chromedriver` 已忽略 |
| 10 | 页面报 `ERR_CONNECTION_REFUSED(-6)` | 服务端 IP 白名单未放通当前出口 IP | 加白名单；`wait_webview_loaded()` 会拦住假通过 |
| 11 | 跑完停在 TalkBack 教程页 | 关闭命令空引号被吞、静默失败 | `settings delete` + 结束 TalkBack 进程 |
| 12 | 切上下文成功但断言全挂 | 误切到系统浏览器上下文（`webview_devtools_remote_<pid>` 不是微信的） | 校验 pid 归属 |
| 13 | 鸿蒙微信 inspect 永远空白 | 鸿蒙版微信不支持 X5/XWeb 远程调试 | 换原生安卓机，或改视觉自动化 |

### 6.4 诊断流程

```
用例失败
├─ 页面/元素找不到
│  ├─ get_current_activity() 在微信首页？ → 启动/入口逻辑问题
│  ├─ 在 MMWebViewUI 但 DOM 为空 → 切错上下文 或 页面未加载（看 current_url / title）
│  └─ 在拦截页（data-module="urlweb"）→ 入口用错，改收藏
├─ 会话建不起来
│  ├─ Appium Settings → 权限/包缺失（3.4）
│  └─ 连不上 4723 → 代理变量
└─ 断言不稳定（时好时坏）
   ├─ 是否在断言可变业务数据？（金额/状态/日期）→ 改为采集
   └─ 是否依赖固定等待？→ 换成 wait_for_element / 页面加载校验
```

### 7.2 已知限制

1. **平台**：仅验证 Android 真机；iOS 需另配 WebDriverAgent，鸿蒙版微信不支持远程调试；
2. **登录态**：依赖人工保持微信登录，未做自动登录；
3. **入口**：收藏入口需要预先收藏，不支持任意 URL 参数化（扫一扫方案未封装）；
4. **域名**：未备案域名在聊天入口必被拦；服务端 IP 白名单未放通时页面只能是错误页；
5. **稳定性**：长链路（约 100~115 秒/条）依赖网络与设备状态，息屏、系统弹窗仍可能干扰；
6. **报告**：暂无 HTML 报告与失败自动截图（`reports/` 为空）；
7. **无障碍服务**：`disable_talkback()` 用 `settings delete` 清空全部无障碍服务，设备上若还有其它读屏/自动化服务需自行恢复；
8. **数据回滚**：`cleanup_after_test()` 只还原客户端现场，不撤销写操作（还款、分期、绑卡等），涉及写数据的用例要单独准备清理逻辑。
